# 提交并推送

为本次目标变更创建范围明确的 Conventional Commit，并推送到已配置的 GitHub 远程仓库。

## 流程

1. 检查 `git status --short --branch`、当前分支、上游分支、远程仓库，以及完整的暂存区和未暂存区差异。
2. 确认哪些变更属于本次工作。不得暂存无关的用户变更、生成文件、机密、凭据或本地配置。如果无法确认归属，或无法安全地区分无关变更，应暂停并询问用户。
3. 运行覆盖本次变更的最小验证。如果验证失败，只修复与任务相关的问题，或说明阻碍；不得在验证失败时默默提交。
4. 只暂存目标路径，检查暂存区差异，并确认不包含机密或无关修改。
5. 选择能准确描述变更的 Conventional Commit 类型：
   - `feat`：新增用户可见功能
   - `fix`：修复问题
   - `docs`：仅修改文档
   - `refactor`、`perf`、`test`、`build`、`ci` 或 `chore`：根据实际变更选择
6. 使用简洁的提交标题，格式为 `type(scope): 动作式摘要` 或 `type: 动作式摘要`。使用仓库现有语言和术语；标题要具体、准确，不得夸大变更范围。
7. 以非交互方式提交，并在提交信息末尾附上以下共同作者声明：

   `Co-authored-by: Copilot <223556219+Copilot@users.noreply.github.com>`

8. 将当前分支推送到配置的上游分支；如果未配置上游，则推送到 `origin <当前分支>`。绝不强制推送。如果远程分支已发生分叉，应暂停并说明情况，不得改写历史。
9. 验证提交哈希、推送的分支和最终工作区状态。向用户报告提交标题、哈希、远程分支、验证结果及剩余变更。

本流程不创建 Release 或版本标签。用户要求发布新版本时，改用 `release` 技能。
