# Pintia 题库整理为 Markdown

将用户提供的 Pintia 题库 JSON 整理成可阅读、可复习的 Markdown。此 skill 可独立安装：所需的数据字段、题型、填空位置和平台状态规则均收录在本 skill 的[数据格式说明](./references/pintia-json-format.md)中，不依赖仓库中的其他文档。

## 输入与匹配

1. 题库 JSON 是必需输入，必须包含 `questions` 数组。用户可上传、粘贴或明确指定可读取的文件；没有题库 JSON 时请先索取，不得从页面描述、网络或答案 JSON 编造题目。
2. 「我的答案」JSON 是可选输入。若题库和答案 JSON 都有非空 `problemSetId`，二者必须相同；不同时暂停合并并说明原因。
3. 读取本 skill 的[数据格式说明](./references/pintia-json-format.md)，再处理题目和答案。按题目 `id` 与答案项 `problemId` 精确匹配作答及状态。没有 ID 时，仅在题号和题型都存在且组合唯一的情况下，才可按用户要求匹配答案；不能通过题干、选项或题目顺序猜答案。平台状态只能按完全匹配的题目 ID 关联。
4. 答案 JSON 提供的 `answer` 默认作为「我的答案」呈现。仅当答案 JSON 存在时才展示答案；不创建、推断或补写缺失作答。

## Markdown 内容要求

布局不使用固定模板。优先遵循用户对风格、分组、答案显示和详略的要求；未指定时自由选择简洁、适合阅读的组织方式，但必须保留以下可用信息：

- 题集名称（优先使用 `problemSetName`，否则使用 `title`），以及可用的题集跳转链接（优先使用题库 `source`；没有链接时不编造）。
- 题集包含的题型概览（`summaries` 可用时），以及每题的原始题号和题型。题型可以用中文名称或 Pintia 原始类型表示；按题型分组或按原题顺序组织均可，默认保留题目原顺序。
- 题干、结构化选项、题目相关图片及代码/公式。适用时覆盖单选、多选、判断、普通填空、程序填空、普通编程和 SQL 编程题；其他题型保留原题内容并清楚标明可识别的类型。
- 若提供答案 JSON，呈现唯一匹配到的「我的答案」；同时按平台状态明确呈现「平台判定正确」「平台判定错误」或「已提交，正确性未知」等结果。没有匹配状态时写「平台状态未知/未提供」，不能将未知当成正确或错误。

题目可以分组、采用表格或使用逐题小节等不同样式，但要避免表格破坏长代码、公式、图片或多行填空题干。题号和题型应与题目对应，不要把题集标题误作题型。

### 保留原题意

- 题干优先取 `content`；缺失时使用 `prompt`，再考虑 `title`。不要无条件拼接重复字段。仅当题目字段完全相同、确定是重复副本时才去重；相似但不相同的文本应保留必要信息。
- `options` 是结构化选项来源。若题干已包含与 `options` 文本及顺序完全相同的完整选项，不要重复列出；否则保留题干和选项。选项应清楚区分并保持顺序。
- 填空题及程序填空题必须保留每个空的位置和顺序。优先根据题目配置的 `blanks[].index` 在题干相应字符位置插入空格占位线；不要把所有空都移到题尾，也不要因空位索引缺失或无法安全使用而猜测位置。规则详见[数据格式说明](./references/pintia-json-format.md#填空题位置)。
- 保留题干和选项中的可读图片链接。若 `images` 有图片而题干中没有对应图片，按其 `location` 与 `optionIndex` 放到相应题干或选项附近；不要重复插入同一图片。`~/...` 图片路径可转换为 `https://images.ptausercontent.com/...`。不必下载图片或编造缺失图片。
- 保留题目及作答中的代码和公式，不改写代码、公式、选项含义或填空顺序。编程题、SQL 编程题和代码型作答使用 Markdown 代码围栏；围栏长度应足以包住原内容，并保留代码换行。
- 对字段冲突、空位位置无法确定或数据缺失，保留原文；必要时只对该题加一句简短说明，不编造缺少的题干、选项、题号、答案或图片。

### 我的答案与平台正确性

- 答案 JSON 的作答是用户提交/提供的答案，不是标准答案。标注为「我的答案」，不得改称标准答案或解析。
- 依据答案项的 `problemStatus` 显示平台评测状态：
  - `PROBLEM_ACCEPTED`：平台判定正确/通过。
  - `PROBLEM_WRONG_ANSWER`：平台判定错误。
  - `PROBLEM_SUBMITTED`：已提交，但该状态本身不表示正确或错误。
  - `PROBLEM_NO_ANSWER`：平台状态为未作答；不应把它描述为已有作答或正确/错误。
  - 缺少状态或状态值无法识别：正确性未知/未提供。
- 状态只说明平台对该次作答的记录，不外推为任何其他答案的正确性。用户明确核实或标注正确性的，可按用户说明呈现，并与平台状态区分。
- 若用户明确要求 AI 解题，另标为「AI 参考答案 / 待核对」，与「我的答案」及平台评测分开。

## 输出文件

- 用户指定输出位置时写入该位置。否则若源题库文件路径可用，将 Markdown 保存到源文件旁，文件名使用 `<题库标题>-复习题库.md`；不得覆盖已有文件，必要时添加序号。
- 没有可写入的源文件位置时，在回复中提供完整 Markdown。
- 只有用户明确要求创建或修改 JSON 文件时才输出 JSON。题库 JSON 和答案 JSON 的本 skill 示例分别位于 [question-bank.template.json](./templates/question-bank.template.json) 和 [answer-json.template.json](./templates/answer-json.template.json)；模板占位值不是实际题目、ID 或可回填答案。遵守本 skill 的[数据格式说明](./references/pintia-json-format.md)。
- 回复中简要说明输出位置即可。不要在复习 Markdown 中加入与复习无关的数据质量清单、免责声明或整理过程说明。

## 边界

- 不通过外部页面、网络或隐藏数据补充题目、答案、评测状态或图片。
- 不得把最近提交内容、模型推测或未知状态自动等同于标准答案或正确答案。
- 本 skill 只整理复习资料，不执行 Pintia 页面回填或保存操作。
