# Pintia 题库题干清洗规则

## 1. 目的与适用范围

本文规定如何从 Pintia 题库 JSON 中识别、清洗并检查题干，供题库导入、Markdown 导出或其他需要呈现题目的功能复用。规则不依赖具体分支、页面或导出格式。

Pintia 不保证题干只存在于某一个字段。以下规则来自对现有导出样本的观察：样本中的 161 道题可用这些规则识别，但没有逐题与 Pintia 页面核对。因此，字段优先级和占位文本是实用启发，不是 Pintia API 的稳定契约；遇到新题型、新模板或无法判定的数据，应保留来源信息并提示复核，不要静默丢弃内容。

## 2. 候选字段与优先级

常见候选字段：

| 字段 | 说明与风险 |
| --- | --- |
| `content` | 通常是完整的 Markdown 正文，优先使用；少数题可能只含平台样例或模板文本。 |
| `apiData.description` | 可包含实际呈现描述；有时与 `content` 不同，有时只存在空格或格式差异。 |
| `prompt` | 常是 `content` 的纯文本或归一化镜像，可能丢失换行、空格或平台标记。 |
| `title` | 元数据摘要；有时是可用题干，但 SQL、填空等题型的标题可能远短于正文，不应常规优先使用。 |

推荐顺序：

1. 优先检查 `content`。
2. 如果它是已知平台样例/模板，而非真实题干，则尝试 `apiData.description`。
3. 再尝试 `prompt`。
4. 前述字段都不可用时才回退到 `title`；记录“使用标题回退”的诊断，供人工确认完整性。

不能仅因两个字段不同就认定其中一个错误。特别是 `title` 与正文通常不是逐字相同的文本。

### SQL 模板的特殊情况

`content` 若以 `这是一个SQL编程题模板。` 开头，先只剥掉这个模板前缀，再检查后续正文：

- 后面有真实题目、表结构或样例时，保留这些内容；不能因为开头是模板就直接退回短 `title`。
- 剥掉前缀后仍为空或明显只是模板说明时，继续尝试其他候选字段。
- “至少 20 个字符”可作为初始的正文长度启发，但不能当作真实性证明；应结合题型和后续内容复核。

## 3. 平台样例与模板文本

以下开头通常表示占位内容，而不是真实题干：

- `这是一个单选题的样例。答案为…`
- `这是一个判断题的样例。答案为…`
- `这是一道单选题的样例…`、`这是一道判断题的样例…`
- `这是一个SQL编程题模板…`
- `这是一道填空题模板…`
- `这是一个主观题模板。请在这里写题目描述。`
- `请在这里写题目描述…`

不要只匹配固定完整句子；可以用开头模式识别，但应保留原始文本用于诊断。模板正文里出现真实任务时，只移除已识别的模板说明，不要把整段正文一起删除。

SQL 题正文中的下列平台提示可视作模板占位行，在确认属于模板提示后移除：

- `请在这里写定义表结构的SQL语句。`
- `请在这里给出输出样例。`

不要用宽泛的 `请在这里` 或 `模板` 全局替换规则：题目正文可能会合法地讨论模板或要求用户编写内容。

## 4. 清洗顺序

清洗应在生成 Markdown 或页面内容之前完成。建议保留原始字段，并按以下顺序处理：

1. **解析并保留原始字段。** 至少保留所选字段名、原始 `content`、题型和题目 ID，便于排查错误。
2. **选取题干来源。** 按第 2 节优先级过滤已知模板；记录来源，以及是否使用了标题回退。
3. **先处理填空位置。** `blanks[].index` 是相对于原始 `content` 的字符偏移；必须在替换 HTML、空白、平台标记或改用归一化后的 `prompt` 前应用。只有选中的正文与原始 `content` 对应时才使用这些索引。
4. **识别已有填空标记。** 如果正文已经含 `[填空1]`、`【填空1】` 等标记，按出现顺序替换为目标格式的填空占位符；此时不要再根据索引插入另一组占位符。
5. **规范化文本表示。** 将 `<br>` 转为换行、`&nbsp;` 和不换行空格规范为空格；将平台转义的 `\____\_` 还原为 `____`。保留 Markdown、代码块和有意义的换行。
6. **清理平台标记。** 在记录其空位数量后，移除 `@[](n)`；清理已识别的尾部 `填空位置：________…` 提示，但不要因此把唯一题干内容清成空串。
7. **处理图片与选项。** 按第 5 节规则规范化图片。是否把正文中内嵌选项移到独立选项区，取决于目标输出格式；若分离，只能在确认是完整的标号选项列表后截取。
8. **生成导出并附带诊断。** 题干正文与“待复核”警告分开保存；不要把内部诊断文字拼进用户题干。

题干选择、题干清洗、Markdown 渲染应是不同步骤。渲染层仍需按应用的安全规则净化 Markdown/HTML 和校验图片 URL。

## 5. 填空、选项、ID 与图片

### 填空题

- `@[](2)` 等平台标记提供空位数量线索。删除标记前先记录数量。
- 若存在 `blanks[].index`，以原始 `content` 为偏移基准；对索引排序后插入占位符。
- 若正文已有 `[填空n]` 或 `【填空n】`，按出现顺序替换，不要重复插入索引占位符。
- 可以移除尾部纯提示行 `填空位置：________、________`；其下划线不应再次计为空位。
- 有多个可用来源时，比较正文标记、配置空位数和答案数组长度。数量不一致应报告复核，不要凭空补答案或悄悄截断。

### 选项

当题库同时提供 `options[]` 与正文中的内嵌选项时，只有检测到与选项内容对应的连续标号（如 `A.`、`B.`、`C.`）才认定正文末尾是选项列表。不能因为选项文字出现在题干中就判定选项已内嵌；例如题干可能直接提到 `SELECT`、`INSERT` 等词。

若导出格式需要独立选项区，确认标号顺序和选项内容均吻合后才从题干尾部移除；否则保留原文并提示复核。

### 题目与答案 ID

- 题目使用 `questions[].id` 与答案文件的 `answers[].problemId` 做精确匹配。
- `apiData.problemId` 可能是另一种 ID，不应替代题目自身的 `id`。
- 不要在 ID 不匹配时按题号静默兜底；报告未匹配数量及匹配率，避免答案被关联到错误题目。

### 图片

- 正文已含 Markdown 图片时，先保留并规范化该图片；不要再把 `images[]` 中同一张图重复插入正文。
- `~/xxx.png` 是 Pintia 图片占位路径时，可按已确认的数据来源转换成 `https://images.ptausercontent.com/xxx.png`，或优先使用 `images[]` 中与其对应的 HTTPS URL。
- 其他协议或无法确认来源的图片不要直接放宽 URL 限制；沿用目标应用的安全策略，并报告未解析图片。
- 主观题答案中的 `{PTA_URL}` 可能是离线无法解析的私有图床占位符。保留原值，并在题干/答案之外标记“图片地址未解析”，不要伪造链接。

## 6. 复核清单

以下规则用于发现可疑数据，不应一概作为自动删除条件：

- 选中的题干为空、只剩平台样例，或最终内容明显短于该题型应有内容。
- 使用了 `title` 回退，尤其是 SQL、程序或填空题。
- 清洗后仍有 `这是一个…样例`、`请在这里…`、`@[]`、未处理的 `[填空n]` 等模板/平台标记。
- 单选题选项数量异常，或需要独立选项时找不到连续的字母标号。
- 填空标记数、配置空位数、答案数组长度不一致。
- 按题型预期应包含表结构/输入输出样例的 SQL 题，只剩短摘要；注意并非每道编程题都有相同章节格式。
- 同一图片重复出现、图片地址仍为 `~/…`、`{PTA_URL}` 未处理，或文本末尾残留 `&nbsp;` 等转义。
- 题目 ID 与答案 ID 匹配率为 0 或显著异常。
- `title` 与正文差异很大。该差异只能作为人工复核信号，不能单独证明题干有误。

可以把每题的来源字段、清洗后的文本、命中的规则和告警保存为独立诊断记录，方便在导出前检查；不建议静默修剪无法确认含义的正文。

## 7. 可靠性边界

这些规则来自有限样本，不等于 Pintia 对所有题型、课程或未来 API 版本的保证。特别是长度阈值、模板文案、选项格式和图片路径都可能变化。若要求“与 Pintia 页面逐字一致”，仍需用代表性题库抽样对照页面，并把新观察到的结构补充到测试和本文中。
