# 题间 · 个人刷题室 — 软件设计说明（SDD）

## 1. 文档目的与范围

本文描述当前仓库已实现的产品行为、模块边界、数据契约和验证方式，作为后续需求变更及实现的基线。它不代表尚未实现的后端服务或平台集成。

## 2. 产品概述

题间是一个由浏览器本地运行的单页刷题工具。应用从平台题库目录读取题库 JSON 和配套答案 JSON；用户也可导入从当前项目约定来源导出的题库 JSON 和答案 JSON。在题库管理页整理题目后，进入练习页完成练习和查看参考答案。

### 目标

- 以题目 ID 为依据关联题库和参考答案。
- 支持题库整理、合并、随机组题、逐题或总览式作答。
- 在不上传用户导入的题库、答案及作答记录的前提下完成练习。

### 非目标与限制

- 当前无服务端、用户账号、云同步、自动保存或站点存储；平台静态题库随站点发布，用户导入的数据在刷新页面后需重新导入。
- 不访问 Pintia API、不向 Pintia 提交作答，也不自动执行编程答案。
- 不执行通用自动判分。仅当个人答案记录带有平台评测状态，且题型支持可靠比对时，练习状态才结合当前作答和该记录进行保守分类；主观题、程序题不自动比对，缺少可靠依据时显示待判定。
- 支持的是本项目可识别的 JSON 结构，不承诺兼容任意题库导出格式。

## 3. 用户流程与行为规格

### 3.1 导入与题库管理

1. 应用读取静态题库目录的 `catalog.json`，逐项获取题库及配套答案 JSON；每份题目和答案均通过现有解析器校验，失败项会在提示中列出原因，不阻止其他有效项载入。
2. 用户也可一次选择多个 JSON 文件。应用逐个解析；有效题库会加入题库列表，解析失败的文件会在提示中列出原因，失败文件不阻止其他文件导入。
3. 题库通过顶层 `questions` 数组识别，答案通过顶层 `answers` 数组识别。
4. 同批导入的答案优先按 `problemSetId` 匹配题库；无法按 ID 唯一匹配时，使用规范化后的文件名或题库标题匹配。匹配不唯一、无匹配或同批多个答案竞争同一题库时，不自动配对，用户可在题库卡片单独导入答案。
5. 单独导入答案时校验 `problemSetId`（当答案和题库均提供 ID 时必须相同），再按答案 `problemId` 与题目 ID 对应。未匹配答案不会按题号兜底。
6. 合并至少两份题库。题目按所选题库顺序拼接；仅对非空且重复的题目 ID 去重，保留第一次出现的题目和答案；无 ID 题目不去重。合并题库重新编号，且不关联单一题集 ID。
7. 用户可以选择任一题库开始练习。切换题库时，当前练习快照保存在该题库条目内存中；切回时恢复。此状态不跨页面刷新保存。
8. 题库列表可按目录分类和标题筛选；本地导入、合并及无分类题库分别显示对应标签。筛选时保留隐藏题库的合并选择，“全选当前结果”只切换当前可见题库。

### 3.2 练习与作答

- 初次进入题库时，当前题组为该题库的全部题目；用户可筛选题型，按指定数量随机组题，或仅抽取导入记录标记为 `PROBLEM_WRONG_ANSWER` 的错题。抽题数默认等于当前勾选题型的题目数量之和，调整题型后同步更新。
- 可打乱当前题组，再恢复打乱前顺序；可返回完整题库。
- 支持单题导航和全题总览。点击完成进度会弹出状态窗口，按颜色和文字查看各题状态并通过题号跳转；全题预览与状态窗口分离，总览中可直接作答和提交。
- 单选与判断题选择后即视为完成；多选、填空、程序填空、主观题和编程题需要填写有效作答并显式提交。修改需提交的作答后，完成标记会清除，需再次提交。
- 重做本题集会清空当前题组内的作答与提交状态、保留题组和题目顺序，以便二刷；不影响当前题组之外的作答。
- 进度分为未作答、作答中、正确、错误、部分正确、待判定和需自行核对。平台评测为通过且当前答案与导入记录一致时标为正确；平台未通过且当前答案与导入记录一致时标为错误；平台未通过但答案不同则待判定。平台明确标记部分正确时，当前答案与该记录一致才显示部分正确。
- 单选、多选和判断题可按答案进行比对；填空题仅精确匹配时才显示正确或错误，答案不一致时保持待判定。主观题、程序题不自动比对，完成后显示需自行核对。参考答案由每题独立的“显示答案/隐藏答案”控件管理，在单题和全题预览模式下均可随时查看，不依赖作答或提交状态；没有导入参考答案时显示明确提示。
- 代码答案作为文本编辑和展示，不会被执行。
- 总分仅在题库能提供可靠分值时显示；未知分值显示“未提供”。

### 3.3 内容呈现与外部请求

- 题干、选项和参考答案以 Markdown 呈现；行内换行保留，`$...$` / `$$...$$` 公式由 KaTeX 渲染，代码围栏保留原始代码行。程序填空的 `@@[](n)` 标记或 `fillInTheBlankForProgrammingProblemConfig.blanks` 配置会生成代码块内的可编辑空位；普通填空仍使用题目下方的输入框。原始 HTML 不启用，并使用 DOMPurify 净化渲染结果。
- Markdown 图片与独立图片字段仅接受 HTTPS 地址。图片延迟加载，不发送 referrer；显示题目图片会使浏览器向题库提供的图片主机发出请求。
- Pintia 外链仅从经过校验的 Pintia 题集地址生成，并在新标签页打开。

## 4. 架构与模块职责

应用采用 Vue 3 + TypeScript + Vite 单页结构，不含路由、状态管理库或服务端层。

| 模块 | 职责 |
| --- | --- |
| `src/main.ts` | 引入全局样式并挂载 Vue 应用。 |
| `src/App.vue` | 管理页面切换、题库选择、练习快照切换及全局提示；协调题库和练习 composable。 |
| `src/features/library/LibraryView.vue` | 展示题库列表、导入入口、答案导入、题库合并和开始练习操作；通过事件向上交付文件和操作意图。 |
| `src/features/library/useQuestionLibrary.ts` | 在内存中维护题库条目；协调平台目录载入、用户文件验证与配对、题库合并，并向 UI 提供提示。 |
| `src/features/library/question-bank-catalog.ts` | 读取题库清单及其 JSON 数据，校验地址与结构，并复用领域解析器形成平台题库条目。 |
| `src/features/practice/PracticeView.vue` | 呈现练习设置、题目、输入控件、答案、进度及导航。 |
| `src/features/practice/usePracticeSession.ts` | 管理题组、筛选、作答、提交状态、进度、随机化及可恢复会话快照。 |
| `src/features/common/practice-data.ts` | 定义题库/题目/答案领域类型，实现 JSON 校验、数据规范化、合并和抽题算法。 |
| `src/features/practice/types.ts` | 定义练习作答和会话快照类型。 |
| `src/components/MarkdownContent.vue`、`src/utils/markdown.ts` | 渲染 Markdown，净化输出并限制图片来源为 HTTPS。 |
| `src/styles/common.css` | 全局样式、布局及响应式规则。 |

视图层不直接负责题库 JSON 解析。静态目录位于 `public/question-banks/catalog.json`；清单通过 `questionBankUrl` 和 `answerUrl` 引用题库/答案 JSON，并可通过 `categories` 与每项的 `categoryIds` 提供分类元数据。数据地址可使用相对地址或 HTTPS 地址（本地开发时允许同源 HTTP）。该加载层把数据转换为通用 `QuestionBank`、`AnswerItem` 和分类标签，和练习会话逻辑解耦。功能 composable 使用 Vue 响应式状态，不将用户导入内容或作答状态写入 `localStorage`、`sessionStorage`、Cookie 或远端服务。

## 5. 数据模型与文件契约

以下为当前实现实际依赖的字段；额外字段可忽略。JSON 顶层必须是对象。

### 5.1 题库文件

```json
{
  "title": "题库标题",
  "problemSetId": "set-id",
  "questions": [
    {
      "problemId": "problem-id",
      "number": 1,
      "type": "MULTIPLE_CHOICE",
      "content": "题干",
      "options": ["选项一", "选项二"],
      "score": 2,
      "images": [{ "url": "https://example.com/image.png" }]
    }
  ],
  "summaries": {
    "MULTIPLE_CHOICE": { "totalScore": 2 }
  }
}
```

- `questions` 必须是非空数组。每道题必须有非空字符串 `type`，并至少提供非空的 `content`、`prompt`、`title` 之一，或有效 HTTPS 图片。
- 题目 ID 从 `problemId` 或 `id` 读取；题目序号从 `number`、`questionNumber` 读取，否则按数组位置生成。
- 题干依次尝试 `content`、`apiData.description`、`prompt`、`title`；已知平台样例/模板题干不作为有效来源，SQL 模板前缀在正文足够长时剥离。题干中的 `<br>`、`&nbsp;` 和 Pintia `~/` 图片路径会规范化；选项保留字符串项。
- 题目 ID 优先读取题目自身的 `id`，其次 `problemId`，并用于按 ID 匹配答案。
- 支持解析填空题的配置位置或题干占位符；题干已有 `[填空n]` / `【填空n】` 标记时按顺序替换，不再按配置位置重复插入。平台的 `@[](n)` 标记和尾部填空提示会清理；程序填空的 `@@[](n)` 标记及其配置位置生成代码块内的作答空位。可从摘要总分计算题库总分，否则所有题目分值均有效时汇总题目分值。
- 非 HTTPS 图片 URL 不导入为图片。Pintia 外链只接受 `pintia.cn` / `www.pintia.cn` 上符合题集路径和 ID 校验的地址。

跨导入、刷题和 Markdown 导出复用的详细清洗规则见 [Pintia 题库题干清洗规则](../../docs/pintia-question-cleaning-rules.md)。

### 5.2 答案文件

```json
{
  "problemSetId": "set-id",
  "answers": [
    {
      "problemId": "problem-id",
      "questionNumber": 1,
      "type": "MULTIPLE_CHOICE",
      "answer": "A",
      "problemStatus": "PROBLEM_ACCEPTED"
    }
  ]
}
```

- `problemSetId` 必须显式为字符串或 `null`；`answers` 必须为数组。
- 每条答案必须有唯一、非空字符串 `problemId`、非空 `type` 和 JSON 合法的 `answer`。`questionNumber` 必须为数字或 `null`。
- 当前按题型验证答案：单选为非空字符串；多选为无重复字符串数组；判断为布尔值；填空为字符串数组；编程题为非空字符串；主观题为字符串。
- 可选 `problemStatus` 必须为字符串。该状态来自导入数据，仅作为展示信息和错题筛选依据。

### 5.3 运行时领域模型

- `QuestionBank`：题库标题、题集 ID、规范化题目列表和总分。
- `PracticeQuestion`：规范化 ID/键、序号、类型、题干、选项、填空数、分值、图片 URL 和可选 Pintia URL。
- `AnswerItem`：题目 ID、题号、题型、参考答案及可选平台状态。
- `BankEntry`：题库、答案映射、导入文件名、合并标记和该题库的练习会话快照。
- `PracticeSessionSnapshot`：当前题组、作答映射、已提交题目、答案显隐状态、位置、顺序恢复信息、预览模式、题型选择及抽题数量。

### 5.4 题库目录文件

```json
{
  "categories": [{ "id": "language.java", "name": "Java" }],
  "banks": [
    {
      "id": "java-course-1",
      "categoryIds": ["language.java"],
      "questionBankUrl": "java/questions.json",
      "answerUrl": "java/answers.json"
    }
  ]
}
```

- `categories` 和题库项的 `categoryIds` 均可省略，以兼容旧目录；缺少有效分类时显示“未分类”。
- 分类 `id` 必须唯一，题库引用的分类必须在目录中定义。`id` 用于关联，`name` 用于显示；题库 JSON 本身不增加分类字段。
- 本地导入和合并题库分别使用“本地导入”和“合并”标签，不写入原题库文件。
- 标题搜索只筛选当前列表显示；“全选当前结果”不会清除已隐藏题库的选择，执行合并时会合并所有已选题库，并提示隐藏选择数量。

## 6. 安全、隐私与可靠性约束

- 平台清单及其列出的题库/答案地址会被浏览器请求；用户导入内容只在当前标签页内存处理，不会上传。除载入平台题库和渲染 HTTPS 图片外，不发送用户数据或作答。
- 不执行用户导入的答案或代码；不得将导入内容拼接为可执行脚本。
- Markdown 禁用原始 HTML，输出必须经 DOMPurify 净化；图片协议限制为 HTTPS。
- 题目与答案通过题目 ID 匹配，避免依赖不稳定的题号；畸形结构、重复答案 ID、类型错误和题集 ID 冲突必须显式报错。
- 文件批量导入允许部分成功，UI 提示应明确列出未匹配或失败项目，不得伪装成完整成功。
- 引入持久化或网络数据源属于产品边界变化，需重新评估隐私承诺、数据生命周期及错误处理，并同步更新本规格和 README。

## 7. 验证与发布

本地环境要求 Node.js `22.18.0` 或更新版本。

```bash
npm ci
npm test
npm run typecheck
npm run build
```

测试使用 Node.js 内建测试运行器（`node --test`），覆盖题库/答案解析与验证、配对和合并、随机抽题及练习会话状态。从仓库根目录向 `main` 分支推送 `practice-room/` 或 Pages 工作流改动，以及手动触发时，GitHub Actions 会运行测试、类型检查与构建；构建产物发布至 GitHub Pages。

## 8. 规格维护

修改导入格式、题库/答案关联、作答流程、数据保存方式、安全边界或部署流程时，应同时更新本文和 README 的使用说明。仅重构内部实现且对外行为不变时，按实际需要更新架构模块表与 Agent 约定。
